# 17. An adversary we did not write, and a split we may not look at

Date: 2026-08-30

## Status

Accepted. Extends ADR 0003 (no detector without eval and a null control) with the
one thing that rule could not supply: a corpus its author did not choose.

## Context

ADR 0003 is a good rule and it has been kept. Every detector limes ships was
admitted on two numbers, over a positive corpus, a benign corpus and a beaten
null control, with the confusion matrix published and the false positives named.

All of those corpora were written by limes's author.

That is enough to answer *"does this detector do what I meant it to do?"* It
cannot answer *"does it catch attacks?"*, and only the second question is a
security claim. The gap is not a detail of methodology; it is the difference
between a test and a measurement. A rules engine graded on cases written by the
person who wrote the rules will score well, and the score says nothing about an
attacker who never read them.

Two facts made this urgent rather than theoretical.

The corpora are **small**: eleven injection cases across three languages, eight
benign inputs. At n=8 the harness's own power statement already said the quiet
part — a false-positive regression smaller than **five of eight** was invisible.
A clean sheet over eight inputs is a fact about the experiment.

And limes is being **published**. From the day it is on an index, the numbers in
its README are read as claims about the world rather than as notes about a
repository.

## Decision

**limes vendors at least one adversary corpus it did not write, and publishes the
number it gets on it, whatever the number is.**

The first is NVIDIA's **garak** (`garak.probes.latentinjection`, Apache-2.0),
copied by value into `eval/corpus/garak/` with provenance, and regenerable by
`scripts/vendor_garak_corpus.py`. Its indirect-injection family — an instruction
buried in a report, a résumé, a whois record, a document handed over for
translation — maps exactly onto the leg limes claims to guard (ADR 0012), so it
tests a stated capability rather than a straw one.

Four properties, each of which the corpus would be worth much less without.

**1 — The dependency runs one way, at vendoring time only.** limes does not
depend on garak: not at runtime, not in the gate, not in an extra. This is ADR
0004's rule applied again, and the same rule the Tessera corpus was copied under.

**2 — A `dev` split and a `holdout` split, assigned by the prompt's own hash.**
The first nibble of `sha256(prompt)` sends it to `dev` (`0`) or `holdout` (`1`);
everything else is not vendored, which is also how the 15 MB full product becomes
370 kB. The rule is uniform, reproducible from the prompt alone, and — the point
— **unsteerable**: an author cannot move an inconvenient case out of `holdout`
without changing the case, which changes its hash.

> **The protocol: rules may be written against `dev`. `holdout` is scored once,
> with the rules frozen.**

A rule written while looking at `holdout` turns `holdout` into a second `dev`,
and the published number silently stops meaning what the table says. Nothing can
enforce this but the person doing it, so the tooling helps rather than trusts:
`python -m limes.eval.external_harness` reports **dev only** by default, and the
held-out number exists only when somebody deliberately passes `--split all`.

**3 — The control is derived, not written.** For every attack
`top_instruction + document(injection)`, the benign control is *the same*
`top_instruction + document` with the injection removed. The two differ by
exactly the attack. A detector that fires on both has learnt the document rather
than the injection, and the matrix shows it. Because the control is derived from
the attack's own data, it cannot drift out of step with it — which a second file
would, eventually, on some Tuesday.

The by-product matters as much as the design: **192 matched controls** replace
eight general benign inputs, and the false-positive claim's minimum detectable
effect goes from *five of eight* to **0.026**.

**4 — A declared non-capability is measured too.** `LatentJailbreak` asks the
model for a toxic sentence. That is a content-policy jailbreak, not an
instruction override, and limes has never claimed it. It is vendored anyway and
scored on its own row, because a perimeter stated in prose is an assertion and a
perimeter with a number beside it is a measurement.

**The external number is published next to the internal ones, not instead of and
not below them.** `eval/matrices/external_injection.md` is generated by
`make eval` like every other matrix, and the README carries the external figure —
the uncomfortable one — rather than only the friendly one.

## Consequences

- limes now has a number it did not choose. The first run of it was not
  flattering, and that is the entire point: `injection-egress` blocked **3.0 %**
  of garak's dev-split indirect injections at **zero** false positives over 192
  matched documents. It is published, dated, and in the README.
- That number is the honest argument for the classifier layer ADR 0013 frames,
  and a far better one than any prose about rules being "a floor". A reader can
  now see the floor's height.
- A rules change is legitimate when it closes a *structural* gap — a family
  present on one leg and missing on the other — and illegitimate when it matches
  a corpus string. `dev` exists so the first kind can be done honestly;
  `holdout` exists so the second kind cannot hide.
- The corpus is one adversary, one tool, one version, one attack family. It is
  not a benchmark, not a ceiling, and not a claim of coverage. Adding a second
  source is future work and lands under this ADR, not around it.
- `eval/corpus/garak/` ships in the repository and the sdist, never in the wheel.
  From an installed limes the harness declares a blind spot rather than
  reporting an empty table (ADR 0015), and its tests skip with that reason.
